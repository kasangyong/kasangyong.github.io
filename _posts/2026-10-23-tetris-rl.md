10×20 테트리스를 Gymnasium 환경으로 직접 짜서 stable-baselines3 DQN으로 학습시켰다. 한 칸씩 움직이는 조작은 쓰지 않고, "어느 회전으로 어느 열에 놓을지"를 행동 하나에 담았다.

| 항목 | 값 |
|---|---|
| 행동 공간 | v1 `Discrete(5)` 조작 → v2 `Discrete(40)` 배치 (회전 4 × 열 10) |
| 관측 | `Box(226,)` 보드 200 + 현재·다음 피스 14 + 열 높이 10 + 구멍·울퉁불퉁함 2 |
| 네트워크 | MLP 226 → 256 → 256 → 40, 파라미터 134,184개 |
| v2 학습 | 6,507,740 스텝, 누적 109,100판 |
| 학습 중 기록 (ε=0.05) | 평균 점수 2,515 (최근 20판), 최고 16,000 (한 세션) |
| greedy 재평가 200판 (사후, SB3 2.9.0·CPU) | 평균 7,713, 중앙값 6,850, 최고 31,000 |
| 학습 환경 | WSL2, Python 3.12.3, SB3 2.7.1, PyTorch 2.10.0+cu128 |

## 1. 한 스텝을 무엇으로 볼 것인가

환경 코드는 `tetris_env.py` 252줄로 끝난다. 보드는 `int32` 20×10 배열이고 피스 7종은 회전 0 상태의 0/1 행렬만 들고 있다가, 회전이 필요하면 행렬을 뒤집어 전치하는 `rotate_cw`를 n번 적용한다.

```python
def rotate_cw(piece):
    return [list(row) for row in zip(*piece[::-1])]
```

v2의 `step`은 한 번 호출에 피스 하나를 끝까지 처리한다. 행동을 회전과 열로 푼 다음 그 열 맨 위에서 떨어뜨려 착지시키고, 줄을 지우고 보상을 계산한 뒤 다음 피스를 스폰한다.

```python
rot   = int(action) // BOARD_W
col   = int(action) %  BOARD_W
piece = apply_rot(self.current_piece, rot)
pw    = len(piece[0])

# 열 범위 클램핑 (피스 너비 초과 방지)
col = max(0, min(col, BOARD_W - pw))

# 게임 오버 체크: 착지 공간 없음
if not self._is_valid(piece, col, 0):
    self.game_over = True
    return self._get_obs(), -10.0, True, False, {
        "score": self.score, "lines": self.lines_cleared, "steps": self.steps
    }
# ... 생략 (이전 보드 특성 저장)
y = self._drop_y(piece, col)
self._place(piece, col, y)
```

착지 위치는 `y = 0`부터 한 칸씩 내려 보다가 더 내려갈 수 없는 곳으로 잡는다.

```python
def _drop_y(self, piece, x):
    """피스를 열 x 에서 떨어뜨렸을 때 착지하는 y 반환."""
    y = 0
    while self._is_valid(piece, x, y + 1):
        y += 1
    return y
```

점수는 표준 테트리스 표 `[0, 100, 300, 500, 800]`를 레벨 배율 없이 그대로 썼다. 보상은 점수와 따로 계산해서, 학습에는 보상을 쓰고 성능을 보고할 때는 점수를 썼다.

## 2. 행동 공간: 조작 5개에서 배치 40개로

{% include embed/video.html src='/assets/img/posts/tetris-rl/explainer.mp4' poster='/assets/img/posts/tetris-rl/explainer-poster.jpg' title='행동을 조작 단위 Discrete(5)에서 배치 단위 Discrete(40)로 바꾸면 결정 하나가 피스 하나가 되고 보상이 그 스텝에 붙는다' loop=true %}

처음 버전(v1)의 행동은 `Discrete(5)`였고, 한 칸 이동이나 회전 같은 조작 단위로 짰다. v1 환경 코드를 남겨 두지 않아서 행동 5개가 정확히 무엇이었는지는 확인할 수 없다. 대신 저장한 모델 `tetris_dqn.zip`의 메타데이터에 행동 공간과 학습 결과는 남아 있다.

| | v1 | v2 |
|---|---|---|
| 행동 공간 | `Discrete(5)` | `Discrete(40)` |
| 관측 | `Box(226,)` | `Box(226,)` |
| 하이퍼파라미터 | 같음 | 같음 |
| 저장 시점 스텝 | 500,000 | 6,507,740 |
| 저장 시점 판 수 | 2,906 | 109,100 |
| 마지막 100판 평균 보상 | −53.31 (100판 모두 음수) | +88.12 |
| 마지막 100판 평균 길이 | 276.4 스텝 | 97.0 스텝 |

조작 단위에서는 줄을 지워 받는 보상이 그 결과를 만든 입력보다 여러 스텝 늦게 들어온다. 피스 하나를 원하는 자리에 놓으려면 이동과 회전을 몇 번 누른 다음 떨어뜨려야 하니, 에이전트는 "어디에 놓았더니 좋았다"를 그 몇 스텝에 걸쳐 거꾸로 나눠 배워야 한다. 배치 단위로 바꾸면 결정 하나가 피스 하나에 정확히 대응하고, 보상도 그 스텝에 바로 붙는다. 환경 파일 맨 위에 "인과관계가 명확해 DQN이 빠르게 학습"이라고 적어 둔 것도 그래서다.

다만 v1과 v2의 보상 숫자를 나란히 놓고 비교하기는 어렵다. v1 보상 함수가 v2와 같았는지 기록해 두지 않았고, 한 스텝이 뜻하는 것도 다르다(v1은 조작 1번, v2는 피스 1개). 커밋한 v1 모델은 50만 스텝 시점 것이다(체크포인트는 80만까지 돌렸다). 확실한 건 그 시점에 마지막 100판이 전부 음수 보상으로 끝났다는 사실이다.

### 40개 중 실제로 다른 배치는 평균 23개

`rot × 10 + col`은 피스와 상관없이 40칸으로 고정돼 있어서, 피스에 따라서는 여러 행동이 같은 배치를 가리킨다.

![피스별 서로 다른 배치 수](/assets/img/posts/tetris-rl/placements-light.png){: .light }
![피스별 서로 다른 배치 수](/assets/img/posts/tetris-rl/placements-dark.png){: .dark }
_행동 40개를 피스마다 (회전 후 모양, 클램핑된 열)로 풀어 중복을 센 값_

- O는 네 회전이 모두 같은 모양이고 폭이 2라 놓을 수 있는 열이 9개뿐이어서, 행동 40개가 배치 9가지로 접힌다.
- I, S, Z는 이 회전 함수로 두 번 돌리면 원래 행렬로 돌아와 모양이 2가지이고, 가로(폭 4 또는 3)와 세로(폭 1 또는 2)를 합치면 17가지다.
- T, J, L은 모양 4가지가 모두 달라서 34가지다.

7종을 평균하면 162 / 7 ≈ 23.1이다. 중복이 있다고 정답이 바뀌지는 않지만 부작용이 두 가지 있다. 같은 배치의 Q값을 여러 출력이 따로따로 배워야 하고, 탐험도 고르지 않게 된다. 폭 3짜리 피스에서 무작위 행동을 뽑으면 열 7, 8, 9가 전부 열 7로 클램핑되니 오른쪽 끝 배치가 다른 열보다 3배 자주 시도된다. greedy로 200판을 돌려 봐도 고른 행동의 7.9%가 클램핑되는 열 값이었다.

### 이 추상화가 버린 것

피스는 늘 맨 위에서 수직으로 떨어지므로 내려오다 옆으로 밀어 넣는 배치(돌출부 아래로 넣기)는 행동 공간에 없다. 회전도 스폰 자리에서 한다고 보고 경로상의 충돌은 검사하지 않는다. 실제 게임에서 가능한 배치 일부를 버리고 행동 공간을 40칸 고정 크기로 얻은 셈이다.

## 3. 상태 표현: 보드 200칸에 요약 특징 26개

```python
def _get_obs(self):
    board_flat = self.board.flatten().astype(np.float32)

    cur_oh = np.zeros(7, dtype=np.float32); cur_oh[self.current_idx] = 1.0
    nxt_oh = np.zeros(7, dtype=np.float32); nxt_oh[self.next_idx]    = 1.0

    heights      = self._col_heights()
    holes_norm   = np.array([self._holes()           / (BOARD_H * BOARD_W)], dtype=np.float32)
    bump_norm    = np.array([self._bumpiness(heights) / (BOARD_H * BOARD_W)], dtype=np.float32)
    heights_norm = heights / BOARD_H

    return np.concatenate([board_flat, cur_oh, nxt_oh, heights_norm, holes_norm, bump_norm])
```

| 구간 | 차원 | 값 범위 |
|---|---|---|
| 보드 | 200 | 0 / 1 |
| 현재 피스 one-hot | 7 | 0 / 1 |
| 다음 피스 one-hot | 7 | 0 / 1 |
| 열 높이 / 20 | 10 | 0 ~ 1 |
| 구멍 수 / 200 | 1 | 0 ~ 1 |
| 울퉁불퉁함 / 200 | 1 | 0 ~ 1 |

배치 단위로 행동하면 피스의 현재 x, y, 회전은 결정에 쓰이지 않아서 관측에서 뺐고, 현재 피스 종류와 다음 피스만 남겼다. 열 높이, 구멍, 울퉁불퉁함은 보드 200칸에서 계산할 수 있지만 MLP가 알아서 뽑아내길 기다리지 않고 직접 넣어 줬다.

구멍은 각 열에서 가장 위 블록보다 아래에 있는 빈칸 수이고, 울퉁불퉁함은 이웃한 열 높이 차의 절댓값 합이다. 둘 다 200으로 나눴는데 실제 값은 그만큼 커지지 않으니 입력이 작게 들어간다. 게임이 끝날 때 구멍이 평균 18개 정도(7절 greedy 재평가 기준)여서 정규화하면 0.09 근처다.

## 4. 보상 설계

```python
# 줄 클리어: 명확한 주 목표
line_rewards = [0, 5.0, 12.0, 20.0, 40.0]
reward = float(line_rewards[n_lines])

# 홀 증감 패널티 (delta만, 절대량 제거)
reward -= (new_holes - prev_holes) * 0.5

# 최고 높이 증감 패널티 (delta만)
reward -= (new_max_h - prev_max_h) * 0.3

# 울퉁불퉁함 패널티
reward -= self._bumpiness(new_heights) * 0.02
```

게임 오버 −10까지 붙여 식으로 쓰면 다음과 같다.

$$
r_t = L(n_t) - 0.5\,(H_{t+1} - H_t) - 0.3\,(M_{t+1} - M_t) - 0.02\,B_{t+1} - 10\cdot[\text{game over}]
$$

$L$은 지운 줄 수별 보상, $H$는 구멍 수, $M$은 최고 높이, $B$는 울퉁불퉁함이다. 막힌 배치를 고른 스텝은 다른 항 없이 −10만 받는다.

### 줄 클리어 보상과 점수 표의 비율

| 지운 줄 | 보상 | 1줄 대비 | 점수 | 1줄 대비 |
|---|---|---|---|---|
| 1 | 5 | 1.0 | 100 | 1.0 |
| 2 | 12 | 2.4 | 300 | 3.0 |
| 3 | 20 | 4.0 | 500 | 5.0 |
| 4 | 40 | 8.0 | 800 | 8.0 |

4줄만 점수 표와 똑같이 8배로 맞췄고 2줄과 3줄은 점수 표보다 덜 쳐준다. 줄당으로 나누면 보상이 5, 6, 6.7, 10이라 한 번에 여러 줄을 지울수록 커진다.

### 구멍과 높이는 증감분, 울퉁불퉁함은 절대량

구멍과 높이 항은 절대량으로 매기다가 증감분만 남기는 쪽으로 바꿨다. 절대량 페널티는 그 상태가 유지되는 한 매 스텝 다시 깎여서, 구멍 하나 만든 실수가 이후 수십 스텝 내내 벌점으로 돌아온다. 증감분이면 구멍을 만든 그 수에서 한 번만 깎이고 구멍을 메우면 그만큼 돌려받는다.

증감분 항을 한 판 동안 더하면 중간 항이 모두 소거된다.

$$
\sum_{t=0}^{T-1} -0.5\,(H_{t+1} - H_t) = -0.5\,(H_T - H_0) = -0.5\,H_T
$$

그래서 판 전체로 보면 구멍 항은 "마지막 판의 구멍 수 × 0.5", 높이 항은 "마지막 최고 높이 × 0.3"과 같다. 두 항이 하는 일은 판 전체 보상의 크기를 정하는 것보다 어느 수가 나빴는지를 그 수에 바로 알려 주는 쪽에 가깝다. 재평가 데이터로 검산해 보면 맞아떨어진다. greedy 200판에서 끝날 때 구멍이 평균 17.97개, 최고 높이가 평균 19.155였고, 구멍 항 합계는 판당 −8.98(= −0.5 × 17.97), 높이 항은 −5.75(≈ −0.3 × 19.155)였다.

![판당 보상 항목별 합계](/assets/img/posts/tetris-rl/reward-breakdown-light.png){: .light }
![판당 보상 항목별 합계](/assets/img/posts/tetris-rl/reward-breakdown-dark.png){: .dark }
_greedy 200판 평균. 다섯 항의 합 280.33이 판당 총 보상과 일치한다_

울퉁불퉁함 항만 절대량으로 남아 있다. 피스마다 그 시점의 울퉁불퉁함을 깎으므로 판이 길어질수록 쌓이고, 페널티 가운데 가장 크다(판당 −42.4, 피스당 약 −0.22). 그래도 줄 클리어 보상이 피스당 평균 1.77이니 오래 살아남는 편이 여전히 이득이다. 구멍·높이와 같은 원칙을 따르면 이 항도 증감분이어야 맞는데, 바꿨을 때 어떻게 달라지는지는 실험하지 않았다.

## 5. 알고리즘과 하이퍼파라미터

알고리즘은 stable-baselines3의 `DQN`과 `MlpPolicy`를 그대로 썼다. 기본값에서 바꾼 항목과 그대로 둔 항목을 같이 적었다.

| 파라미터 | 사용 값 | SB3 기본값 |
|---|---|---|
| `learning_rate` | 1e-4 (상수) | 1e-4 |
| `buffer_size` | 100,000 | 1,000,000 |
| `learning_starts` | 2,000 | 100 |
| `batch_size` | 64 | 32 |
| `gamma` | 0.99 | 0.99 |
| `train_freq` / `gradient_steps` | 4 / 1 | 4 / 1 |
| `tau` | 0.005 | 1.0 |
| `target_update_interval` | 1,000 | 10,000 |
| `exploration_fraction` | 0.3 | 0.1 |
| ε 시작 → 끝 | 1.0 → 0.05 | 1.0 → 0.05 |
| `net_arch` | [256, 256] | [64, 64] |
| `max_grad_norm` | 10 (기본값) | 10 |

### tau와 target_update_interval이 겹친다

SB3 DQN은 `target_update_interval`마다 polyak 업데이트를 한 번씩 한다.

```python
if self._n_calls % max(self.target_update_interval // self.n_envs, 1) == 0:
    polyak_update(self.q_net.parameters(), self.q_net_target.parameters(), self.tau)
```

기본값(1만 스텝마다 `tau=1.0`)이면 1만 스텝마다 통째로 복사하는 hard update가 된다. 나는 1,000스텝 간격에 `tau=0.005`까지 줘서 두 장치를 한꺼번에 걸었다. 1,000스텝에 한 번 0.5%씩만 따라가니 타깃 네트워크가 온라인 네트워크와의 차이를 63% 줄이는 데 업데이트 200번, 곧 20만 스텝이 걸린다($0.995^{200} \approx 0.367$). 흔히 쓰는 매 스텝 `tau=0.005` soft update보다 1,000배 느린 셈이다. 650만 스텝 동안 타깃 업데이트는 약 6,500번 일어났다. 의도한 값인지 확인하지 않고 둘 다 넣은 설정이었고, 다른 조합과 비교해 본 실험은 없다.

### 네트워크 크기

226 → 256 → 256 → 40 MLP의 파라미터 수는 이렇게 나온다.

$$
(226 \cdot 256 + 256) + (256 \cdot 256 + 256) + (256 \cdot 40 + 40) = 58{,}112 + 65{,}792 + 10{,}280 = 134{,}184
$$

온라인·타깃 두 벌을 float32로 저장하면 1,073,472바이트이고, `policy.pth` 1,078,271바이트와 거의 같다. 출력이 5개인 v1은 125,189개였다.

## 6. 학습 기록: 곡선 대신 남은 것

학습 곡선은 남아 있지 않다. `tensorboard_log`를 켜지 않았고 콜백은 10판마다 표준 출력에 한 줄 찍는 게 전부였다. 실시간 상태를 0.3초마다 덮어쓴 `game_state.json`도 마지막 값만 남는 구조다.

그나마 SB3가 모델을 저장할 때 최근 100판의 보상과 길이(`ep_info_buffer`)를 같이 직렬화해 둔다. 커밋해 둔 두 모델에서 이 값을 꺼내 그렸다.

![v1과 v2의 저장 직전 100판](/assets/img/posts/tetris-rl/last100-light.png){: .light }
![v1과 v2의 저장 직전 100판](/assets/img/posts/tetris-rl/last100-dark.png){: .dark }
_왼쪽은 판당 보상, 오른쪽은 판당 스텝 수. v1의 스텝은 조작 1번(행동 5개의 정확한 정의는 확인할 수 없다), v2의 스텝은 피스 1개다_

v2의 판당 보상은 −28.4부터 274.7까지 넓게 퍼져 있다. ε=0.05로 섞이는 무작위 배치도 한 원인으로 보이지만, greedy에서도 판당 보상이 20.8~1,229로 퍼지니 그것만으로는 설명이 안 된다. 분포 자체는 7절의 ε=0.05 재평가(평균 보상 86.04, 평균 95.5피스)와 거의 같다.

## 7. 평균 2,515와 최고 16,000은 어떤 조건의 숫자인가

README와 포트폴리오에 적은 평균 2,515, 최고 16,000은 `game_state.json`의 `avg_score`, `best_score`에서 가져왔다. 이 값을 만드는 코드는 다음과 같다.

```python
"avg_reward": float(np.mean(self.ep_rewards[-20:])) if self.ep_rewards else 0.0,
"avg_score": float(np.mean(self.ep_scores[-20:])) if self.ep_scores else 0.0,
"best_score": int(max(self.ep_scores)) if self.ep_scores else 0,
```

여기에는 조건이 세 가지 붙는다.

1. 학습 중인 판에서 나온 숫자다. 행동은 ε-greedy였고 마지막 세션의 ε은 처음부터 끝까지 0.05였다(10절에서 계산).
2. 평균은 최근 20판 기준이다. 100판 평균도, 전체 평균도 아니다.
3. 최고는 그 세션 안에서만 센 최고다. `TrainCallback`이 재개할 때마다 새로 만들어지므로 `ep_scores`도 판 수 `n_ep`도 0부터 다시 센다. README의 "에피소드 35,063+" 역시 이 세션 카운터 값이고, SB3가 누적으로 센 v2 판 수는 109,100이다. README에 적은 시점이 650만+ 스텝이었으니 마지막 세션(3,507,740부터)이 끝나 갈 무렵의 값으로 본다.

그래서 학습이 끝난 정책 자체가 어느 정도인지 따로 재 봤다. 커밋해 둔 `tetris_dqn_v2.zip`(6,507,740스텝)을 불러, 판 번호 g = 0~199마다 `random.seed(g)`, `np.random.seed(g)`를 걸고 두 조건에서 200판씩 돌렸다. greedy는 `play.py`와 같은 `deterministic=True`로, ε=0.05는 학습 중 행동을 흉내 내려고 5% 확률로 40개 중 하나를 무작위로 고르게 했다.

재평가는 2026-10에 Windows CPU, SB3 2.9.0, PyTorch 2.14.0, Gymnasium 1.4.0, pygame-ce 2.5.8로 돌렸다. 학습 때(SB3 2.7.1, GPU)와 버전이 다르니 행동이 완전히 같다고 보장하지는 못한다.

| 조건 | 평균 점수 | 중앙값 | 최고 | 평균 줄 | 평균 피스 | 16,000 이상 |
|---|---|---|---|---|---|---|
| ε=0.05 | 2,968 | 2,700 | 9,900 | 24.7 | 95.5 | 0판 |
| greedy | 7,713 | 6,850 | 31,000 | 63.8 | 196.1 | 13판 |

![조건별 점수 분포](/assets/img/posts/tetris-rl/score-dist-light.png){: .light }
![조건별 점수 분포](/assets/img/posts/tetris-rl/score-dist-dark.png){: .dark }
_같은 모델, 같은 시드 200개. 바뀐 건 5% 무작위 행동뿐이다_

무작위 행동 5%만으로 평균이 2.6배 벌어진다. 학습 중 숫자가 greedy 정책보다 낮게 나온 건 주로 이 차이 때문이라고 본다. ε=0.05 재평가에서 판별 점수의 표준편차가 1,721이니, 20판 평균의 표준오차(약 385)를 감안하면 2,515와 2,968은 비슷한 범위에 들어간다. 기록해 둔 최고 16,000은 ε=0.05 조건으로 3만 판 넘게 돈 세션의 최댓값이어서, 200판 재평가에서는 9,900까지밖에 나오지 않았다.

## 8. 에이전트가 실제로 고른 수

greedy 200판에서 둔 39,210수를 회전과 열로 펼쳐 봤다.

![회전 × 열 행동 빈도](/assets/img/posts/tetris-rl/action-heatmap-light.png){: .light }

한 번에 지운 줄 수도 한쪽으로 쏠려 있다.

| 한 번에 지운 줄 | 횟수 | 비율 |
|---|---|---|
| 1줄 | 7,693 | 76.2% |
| 2줄 | 2,163 | 21.4% |
| 3줄 | 228 | 2.3% |

## 9. 실패 사례: 어떻게 지는가

아래는 중앙값에 가장 가까운 판(시드 67, 6,800점, 170피스)의 최고 높이와 구멍 수다.

![한 판 동안 최고 높이와 구멍 수](/assets/img/posts/tetris-rl/collapse-light.png){: .light }
![한 판 동안 최고 높이와 구멍 수](/assets/img/posts/tetris-rl/collapse-dark.png){: .dark }
_구멍은 거의 줄지 않고 계단식으로 쌓이며, 높이가 그 위를 따라 올라간다_

구멍은 한 번 생기면 좀처럼 메워지지 않는다. 구멍이 있는 줄은 지워지지 않으니 그 위에서만 줄을 지우게 되고, 쓸 수 있는 높이가 점점 줄어든다. 이 판은 처음 47수 동안 구멍이 0~1개였다가 80수에 4개, 100수에 8개, 120수에 11개로 늘었고, 최고 높이가 19에 이른 채 끝났다.

### 179판은 놓을 자리가 남아 있는데 졌다

게임 오버로 가는 길은 두 가지다. 고른 배치가 맨 위 줄부터 막혀 있는 경우(앞의 `_is_valid(piece, col, 0)` 분기), 그리고 놓은 뒤 다음 피스가 스폰 자리에 들어가지 못하는 경우다. greedy 200판 중 179판이 앞의 경우로 끝났는데, 179판 모두 그 순간 놓을 수 있는 행동이 따로 남아 있었다(중복 포함 평균 28.1개, 최소 10개).

환경이 막힌 배치를 고르는 즉시 게임 오버로 처리하므로 이 179판은 에이전트가 고른 한 수로 끝났다. 그래서 막힌 행동의 Q값을 지우고 나머지 중 최댓값을 고르도록 바꿔 같은 200판을 다시 돌렸다.

| | 평균 점수 | 평균 피스 |
|---|---|---|
| greedy | 7,713 | 196.1 |
| greedy + 막힌 행동 제외 | 7,726 | 198.7 |

평균 2.6피스를 더 버텼을 뿐이다. 막힌 배치를 고른 시점의 최고 높이가 평균 19.11(최소 17)이었으니, 그때는 이미 어디에 놓든 몇 수 안에 끝날 판이었다. 실제로 판을 끝낸 건 그 전에 구멍을 쌓으면서 높이를 잃어 간 과정이다.

## 10. 재개 경로에 숨은 것들

650만 스텝은 `--resume`으로 여러 번 이어 붙여 채웠다. 모델 메타데이터의 `_num_timesteps_at_start`=3,507,740을 보면 마지막 세션은 3,507,740스텝에서 시작해 300만 스텝을 더 돌았다. 재개 코드는 짧지만 코드대로 동작하지 않는 곳이 있다.

```python
model = DQN.load(resume_path, env=env)
model.learning_rate = args.lr
# ...
model.learn(
    total_timesteps=args.steps,
    callback=callback,
    reset_num_timesteps=not args.resume,
)
```

### `--lr`은 재개할 때 적용되지 않는다

SB3의 `load`는 저장된 속성을 복원한 뒤 `_setup_model()`을 호출하고, 여기서 그때의 `learning_rate`로 `lr_schedule`을 만든다. 옵티마이저가 보는 건 이 `lr_schedule`뿐이라 로드한 다음 `model.learning_rate`를 바꿔도 실제 학습률은 그대로다. 이번에는 처음부터 끝까지 기본값 1e-4로 학습해서 결과에 영향은 없었다. 하지만 학습률을 낮춰 이어 학습하려 했다면 아무 일도 일어나지 않았을 것이다. `DQN.load(..., learning_rate=args.lr)`처럼 로드 인자로 넘겨야 한다.

### ε 스케줄이 재개 시점마다 다시 계산된다

`reset_num_timesteps=False`이면 SB3는 `total_timesteps`에 지금까지 쌓인 스텝을 더하고 진행률을 `1 - num_timesteps / total_timesteps`로 다시 잡는다. ε은 이 진행률의 앞 30% 구간에서 1.0부터 0.05까지 내려간다.

$$
\varepsilon = \begin{cases} 1.0 - 0.95 \cdot \dfrac{p}{0.3} & p \le 0.3 \\[4pt] 0.05 & p > 0.3 \end{cases}, \qquad p = \frac{\text{num\_timesteps}}{\text{total\_timesteps}}
$$

마지막 세션은 $p = 3{,}507{,}740 / 6{,}507{,}740 = 0.539$에서 시작했으므로 ε이 내내 0.05였다. 문제는 이미 학습한 양보다 `--steps`를 크게 줬을 때다. 예를 들어 50만 스텝에서 기본값 `--steps 3000000`으로 재개하면 $p = 0.5 / 3.5 = 0.143$이 되고, ε은 $1 - 0.95 \times 0.143 / 0.3 \approx 0.55$로 다시 올라간다. 다 배운 정책을 절반 넘게 무작위로 굴리게 된다. 앞쪽 세션들을 어떤 `--steps`로 이어 붙였는지 기록해 두지 않아서, 중간에 이런 구간이 있었는지는 확인할 수 없다.

### 재개하면 빈 리플레이 버퍼로 바로 학습한다

체크포인트를 `save_replay_buffer=False`로 저장했고 `DQN.load`도 버퍼를 불러오지 않으니, 재개할 때마다 버퍼는 빈 채로 시작한다. 그런데 SB3는 학습을 할지와 무작위 워밍업을 할지를 둘 다 `num_timesteps`와 `learning_starts`를 비교해서 정한다.

```python
if self.num_timesteps > 0 and self.num_timesteps > self.learning_starts:
```

재개 직후 `num_timesteps`는 이미 수백만이어서 `learning_starts=2,000`은 아무 역할을 못 한다. 무작위 워밍업 없이 첫 `train_freq`(4스텝)부터 경사 업데이트가 돌고, 버퍼에 들어 있는 전이 몇 개에서 배치 64개를 중복으로 뽑아 학습한다. 세션 첫 2,000스텝 남짓은 처음 학습할 때와 달리 다양성이 거의 없는 데이터로 업데이트하게 된다. 이 구간이 결과에 얼마나 영향을 줬는지는 재지 않았다.

### 카운터가 세션마다 초기화된다

7절에서 봤듯 콜백의 판 수와 최고 점수는 세션 단위로 세고, SB3 내부 카운터(`_episode_num`)는 누적으로 센다. 그래서 두 숫자가 다르다.

## 11. 한계와 다음 단계

- 학습 곡선이 없어서 650만 스텝 동안의 보상 변화는 저장 직전 100판으로만 남았다. 다음 실험과 비교하려면 `tensorboard_log`나 판별 로그 파일부터 켜야 한다.
- 보고한 숫자는 조건이 섞여 있었다. 학습 중 최근 20판 평균(ε=0.05)과 세션 최고를 정책 성능처럼 적었는데, 앞으로는 고정 시드 greedy 평가를 따로 둔다.
- 행동 공간 40칸 중 피스별로 서로 다른 배치는 9~34칸뿐이다. 유효한 배치만 남기는 마스크를 씌우거나 중복을 대표 행동 하나로 접는 방법을 써 볼 만하다.
- 수직 낙하만 허용해서 밀어 넣기가 없고, 돌출부 아래로는 놓을 수 없다.
- 4줄 클리어가 거의 나오지 않는다. 울퉁불퉁함만 절대량으로 남은 비대칭, 그리고 높이 페널티 계수가 우물을 파는 전략과 부딪히는지를 보상 계수를 바꿔 가며 확인해 봐야 한다.
- 하이퍼파라미터는 한 조합만 돌렸다. `tau=0.005`와 `target_update_interval=1000` 조합도 다른 설정과 비교하지 않았다.
- 재개 경로의 `--lr` 무시, ε 재계산, 빈 버퍼 즉시 학습은 아직 고치지 않았다.

v1과 v2는 행동 공간 외에도 학습량과 (아마) 보상까지 달라서, 어떤 요인이 차이를 만들었는지는 분리하지 못했다.
