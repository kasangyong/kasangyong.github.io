## 1. 세계: 격자 위의 장, 그 위의 입자

설계 단계에서 세 가지를 놓고 골랐다. 칸 하나가 생물 하나인 셀룰러 오토마타는 뇌나 몸 크기를 담기 어렵고, Lenia 같은 연속장은 유전체와 종 개념이 흐려서 계통수를 그리기 어렵다. 그래서 환경(화학, 빛, 온도)은 격자장으로, 생물은 위치와 유전체를 가진 입자로 두는 하이브리드를 택했다.

화학장은 8종이다. 열수구에서만 나오는 H₂(`H`), 황화물·Fe²⁺ 묶음(`R`)과 그 산화형(`X`), CO₂·O₂·CH₄(`C`, `O`, `M`), 영양염(`N`), C:N = 6.6으로 고정한 사체(`D`)다.

한 tick은 이 순서로 돈다.

```python
def step(self, n: int = 1):
    w = self.world
    for _ in range(n):
        w.emit_vents()
        w.transport()
        self.chemistry.step()
        self.climate.gas_exchange()
        self.climate.step()
        w.update_light_temp()
        self.life.step()
    self.tick += n
```

`life.step()` 안은 다시 `move → census → think → predate → metabolize → die → weigh_divisions → reproduce`로 나뉘고, 다세포 단계부터 생물체용 커널(`neural`, `swim`, `share_energy`, `develop`, `integrity`, `transition`, `wire`, `tissue`)이 사이사이에 끼어든다.

### 수송은 gather 형태로

확산과 해류 이류는 한 커널에서 계산한다. 해류는 고정된 대순환 유선 함수 `psi` 하나에서 나온다. 칸 모서리에 유선 함수를 두고 면 플럭스를 그 차이로 구하면 발산이 0이 되고, 바위와 수면에 닿는 모서리를 0으로 두면 벽을 통과하는 흐름도 없다.

칸마다 네 면의 플럭스를 직접 모아(gather) 변화량을 만든다. 같은 면을 양쪽 칸이 같은 식으로 반대 부호로 계산하니, 원자 연산 없이도 물질이 float 반올림 수준에서 보존된다.

```python
@ti.kernel
def transport(self):
    # gather form: each face flux is evaluated identically (antisymmetrically) from both
    # sides, so transport conserves every species to float rounding
    for s, x, y in self.delta:
        dc = ti.cast(0.0, CHEM_DTYPE)
        if self.is_water(x, y):
            c = self.chem[s, x, y]
            # right face at x+1: u>0 means flow +x
            if self.is_water(x + 1, y):
                u = self.psi[x + 1, y + 1] - self.psi[x + 1, y]
                cn = self.chem[s, x + 1, y]
                dc += self.cfg.kh * (cn - c) - (u * c if u > 0 else u * cn)
            # ... 생략 (왼쪽·아래·위 면, 사체 침강)
        self.delta[s, x, y] = dc
    for s, x, y in self.chem:
        self.chem[s, x, y] += self.delta[s, x, y]
```

### 화학장은 f64

처음엔 화학장을 f32로 짰다. 정상상태에 들어간 칸은 매 tick 똑같은 연산을 반복하므로 반올림 오차도 같은 방향으로 쌓인다. 생물 없이 돌려 보니 전자 수지 오차가 1만 tick에 9.9e-6, 10만 tick에 2.4e-4로 시간에 비례해 커졌고, 이 추세면 100만 tick에서 기준 0.1%를 넘는다. 화학장과 변화량, 열 부분합을 f64로 바꾸자 같은 10만 tick에서 1.8e-13이 됐다. 대가로 커널 시간이 0.68ms에서 약 1.3ms/tick(추정)으로 늘었는데, 원인은 메모리 대역폭이다. f32로 플럭스를 계산하고 f64로 누적하는 절충안도 시험했지만 이득이 없어 되돌렸다.

## 2. 에너지는 ΔG에서만 나온다

생물이 환경을 바꾸지 못하면 산소 증가 같은 사건은 처음부터 불가능하다. 그래서 "먹이 점수" 같은 추상값 대신 실제 산화환원 반응으로 에너지를 회계했다. 물질마다 전자 단위 $e$와 화학 퍼텐셜 $\mu$를 고정하고, 산화형(CO₂, X, O₂)을 0으로 둔다.

| 물질 | e | μ | μ/e |
|---|---|---|---|
| H₂ | +2 | 2.6 | 1.3 |
| CH₄ | +8 | 7.2 | 0.9 |
| 몸 탄소, 사체 (CH₂O) | +4 | 4.0 | 1.0 |
| R | +2 | 1.4 | 0.7 |
| CO₂, X | 0 | 0 | |
| O₂ | −4 | 0 | |

반응 표는 `reactions.py` 한 파일에 있다. 생물 반응 9개의 커널과 테스트는 이 표를 읽는다. 비생물 6개는 표에 적어 전자·탄소 균형만 테스트하고, `chemistry.py` 커널에는 화학량을 직접 썼다. 원소가 보존되는지는 모든 비생물 경로를 돌리는 수지 테스트로 확인한다(커널의 화학량이 표와 같은지는 테스트하지 않는다).

```python
E_UNITS = {"H": 2, "R": 2, "X": 0, "C": 0, "O": -4, "M": 8, "N": 0, "D": 4, "B": 4}
MU = {"H": 2.6, "R": 1.4, "X": 0.0, "C": 0.0, "O": 0.0, "M": 7.2, "N": 0.0, "D": 4.0, "B": 4.0}

REACTIONS = {
    "h2_chemosynthesis": {"H": -2, "C": -1, "B": 1},
    "sulfur_fixation": {"R": -2, "C": -1, "B": 1, "X": 2},
    "sulfur_oxidation": {"R": -2, "O": -1, "X": 2},
    "photosynthesis": {"C": -1, "B": 1, "O": 1},
    "anoxygenic_photosynthesis": {"R": -2, "C": -1, "B": 1, "X": 2},
    "aerobic_respiration": {"B": -1, "O": -1, "C": 1},
    "anaerobic_respiration": {"B": -1, "X": -2, "C": 1, "R": 2},
    "methanogenesis": {"B": -2, "C": 1, "M": 1},
    "methane_oxidation": {"M": -1, "O": -2, "C": 1},
    # ... 생략 (비생물 6개)
}

def delta_g(rx: dict) -> float:
    return sum(MU[s] * k for s, k in rx.items())
```

`B`는 생물의 몸 탄소다. 수소 화학합성 $2\mathrm{H} + \mathrm{C} \rightarrow \mathrm{B}$라면 $\Delta G = 4.0 - 2 \times 2.6 = -1.2$이고, 세포는 효소 효율 $\eta$를 곱한 만큼 에너지를 얻는다.

$$
\Delta G = \sum \mu_{\text{산출}} - \sum \mu_{\text{입력}}, \qquad
E_{\text{세포}} = \begin{cases} -\Delta G \cdot \eta & \Delta G < 0 \\ -\Delta G / \eta & \Delta G > 0 \text{ (지불)} \end{cases}
$$

### 영구기관을 막는 η < 1

정반응과 역반응은 ΔG 부호만 반대다. 황 탄소고정(ΔG = +1.2, 지불)과 무산소 호흡(ΔG = −1.2, 획득)을 한 바퀴 돌리면 순에너지는 $1.2\eta - 1.2/\eta$이고, $\eta < 1$이면 항상 음수다($\eta = 0.95$에서 −0.123). $\eta = 1$이면 0이 되어 공짜 순환의 경계에 선다. 처음엔 유전자 범위 상한이 1.0이었는데, 단계 2 평가에서 설계의 η < 1이 코드로 강제되지 않는다는 지적을 받고 상한을 0.95로 잘랐다.

빛이 ΔG를 내는 광합성도 같은 규칙을 따른다. 빛으로 $\Delta G/\eta$를 내고 그 몸을 태워 $-\Delta G \cdot \eta$를 돌려받으니 세포가 회수하는 건 쓴 빛의 $\eta^2$뿐이다. 광합성과 호흡을 묶으면 빛으로 충전하는 배터리일 뿐 에너지원이 되지는 않는다. 이 성질들은 테스트로 고정했다.

```python
@pytest.mark.parametrize("eta", [0.3, 0.9, 0.999])
def test_no_free_energy_cycle(eta):
    # fixation (pay ΔG/η) followed by its reverse, anaerobic respiration (gain −ΔG·η)
    cost = delta_g(REACTIONS["sulfur_fixation"]) / eta
    gain = -delta_g(REACTIONS["anaerobic_respiration"]) * eta
    assert gain - cost < 0
```

외부에서 들어오는 에너지는 빛과, 열수구·화산이 공급하는 환원제(H, R)의 μ 두 가지뿐이다.

### 산소는 전자가 빠져나간 만큼 남는다

광합성으로 생긴 O₂는 같은 탄소가 호흡되거나 분해되면 그대로 다시 쓰인다. 장기적으로 O₂가 남으려면 환원력(전자)이 시스템을 빠져나가야 한다. 경로는 둘이다. 해저 칸의 사체 일부가 매 tick 매몰 저장고로 빠지는데, 매몰 1단위가 전자 +4를 들고 나가니 바다에는 O₂ 1단위가 남는다. 대기 메탄이 광분해되면 전자 8e가 수소로 우주에 빠진다. 전자 단위로 쓰면 축적 조건은 이렇다.

$$
4 F_{\text{매몰}} + 8 F_{\text{메탄 탈출}} > 2 (F_{\text{H}} + F_{\text{R}})
$$

설계할 때는 매몰을 주 경로로 생각했는데, 시험 세계 3,000 tick에서 매몰을 끈 실행이 오히려 O₂를 더 남겼다(39.7 대 켠 실행 2.25). 메탄 광분해로 일어나는 우주 탈출이 매몰보다 클 수 있다는 뜻이라, 실제 실행의 O₂ 축적을 매몰만으로 해석하지 않는다.

이 조건이 이어져 바다의 환원제 재고(H, R, CH₄)가 먼저 바닥나야 O₂가 쌓이기 시작한다. 그 소진 기간이 산소 증가의 지연이고, 조건이 언제 성립할지는 광합성 계통이 얼마나 번성하느냐에 달렸다. 일정표를 넣지 않고도 대산화가 늦게 오는 구조가 여기서 나온다.

## 3. 원소 장부

물질이 바뀌는 곳은 두 종류만 허용했다. 시스템 안에서 이동만 하거나(양쪽 양이 정확히 같다), 원천·싱크 누적 슬롯 `world.acc`에 기록하는 것이다. 장부는 C, N, 전자 세 가지를 추적하고 몸 탄소도 총량에 넣는다.

```python
def budget_error(world: World, agents, t0: Totals) -> BudgetError:
    t = totals(world, agents)
    acc = world.acc.to_numpy()
    exp_c = t0.carbon + acc[SRC_C] - acc[SINK_C]
    exp_n = t0.nitrogen + acc[SRC_N] - acc[SINK_N]
    exp_e = t0.electrons + acc[SRC_E] - acc[SINK_E]
    return BudgetError(
        abs(t.carbon - exp_c) / max(t.carbon, 1e-12),
        abs(t.nitrogen - exp_n) / max(t.nitrogen, 1e-12),
        abs(t.electrons - exp_e) / max(t.electron_scale, 1e-12),
    )
```

| 원천 (맨틀 → 시스템) | 싱크 (시스템 → 지각·우주) |
|---|---|
| 열수구: H, R, C, N | 유기물 매몰: 해저 칸 D의 일부 |
| 화산(포아송): 대기 CO₂, H₂ | 메탄 광분해 + 수소 우주 탈출: 전자 8e 손실 |
| | 풍화: 대기 CO₂ → 탄산염 (결빙률에 비례해 멈춤) |
| | N 손실: 매몰 사체의 N + 무산소 칸 탈질 근사 |

전자 오차의 분모로는 총량 대신 기여 절댓값의 합 $\sum \lvert e_i \cdot n_i \rvert$을 쓴다. O₂가 쌓이면 전자 총량 $E$가 0을 지나갈 수 있어서, 총량으로 나누면 0 근처에서 상대오차가 의미 없이 폭발한다.

### 세포와 칸 사이는 `take`와 `give`로만

같은 칸의 세포 수천 개가 한 tick에 같은 H₂를 먹으러 온다. 세포끼리 순서를 정하지 않고 원자적으로 먼저 빼고 모자란 만큼 되돌린다.

```python
@ti.func
def take(self, s: int, x: int, y: int, amount: CHEM_DTYPE) -> CHEM_DTYPE:
    """Atomically withdraw up to `amount` from a cell; never leaves it negative beyond f64
    rounding (~-1e-18) from the subtract-then-refund."""
    got = ti.cast(0.0, CHEM_DTYPE)
    if amount > 0:
        old = ti.atomic_sub(self.world.chem[s, x, y], amount)
        got = ti.min(amount, ti.max(old, 0.0))
        if got < amount:
            ti.atomic_add(self.world.chem[s, x, y], amount - got)
    return got
```

반응 하나를 실행하는 `run`은 이 위에 올라간다. 반응물을 전부 빼 본 뒤 가장 모자란 반응물이 허락하는 비율 `f`만 남기고 나머지를 돌려주고, 같은 비율로 산물을 내놓는다. 화학량 계수는 `reactions.py`에서 미리 만든 정적 표(`INPUTS`, `OUTPUTS`)에서 `ti.static`으로 펼쳐지므로 반응을 추가해도 커널을 손댈 필요가 없다.

```python
for j in ti.static(range(len(INPUTS[rx]))):
    want = CHEM_DTYPE(INPUTS[rx][j][1]) * ext
    got[j] = self.take(ti.static(INPUTS[rx][j][0]), x, y, want)
    f = ti.min(f, got[j] / want)
for j in ti.static(range(len(INPUTS[rx]))):
    self.give(ti.static(INPUTS[rx][j][0]), x, y,
              got[j] - CHEM_DTYPE(INPUTS[rx][j][1]) * ext * f)
for j in ti.static(range(len(OUTPUTS[rx]))):
    self.give(ti.static(OUTPUTS[rx][j][0]), x, y,
              CHEM_DTYPE(OUTPUTS[rx][j][1]) * ext * f)
```

빼고 되돌리는 사이에 다른 스레드가 읽으면 −1e-18 정도의 음수가 보일 수 있다. 그래서 포화항처럼 칸 농도를 원자 연산 없이 읽는 곳은 모두 0으로 클램프했다.

### 원자 연산은 열 단위로 모은다

비생물 화학은 칸마다 매몰량을 싱크에 더해야 하는데, 39만 칸이 같은 주소 하나에 `atomic_add`를 하면 GPU에서 직렬화된다. 실측으로 화학 커널이 0.1ms에서 1.15ms가 됐다. 열(x)마다 부분합을 쌓고 마지막에 1,024개만 합치는 식으로 바꿨다.

```python
if y == self.world.floor[x] - 1:
    bd = self.cfg.k_bury_d * d
    d -= bd
    br = self.cfg.k_bury_r * r
    r -= br
    self.col_sink[0, x] += bd
    self.col_sink[1, x] += bd / CHEM_DTYPE(CN_RATIO)
    self.col_sink[2, x] += 4.0 * bd + 2.0 * br
# ...
for x in range(self.world.w):
    self.world.acc[SINK_C] += ti.cast(self.col_sink[0, x], ti.f64)
    # ... 생략 (N, 전자, 관찰용 매몰 슬롯)
```

### f64 장에 숨어 있던 f32 리터럴

단계 3a에서 대사를 넓히자 N 수지 오차가 2,000 tick 만에 2.6e-9가 되어 회귀 기준 1e-9를 넘었다. C와 전자는 1e-14 이하로 멀쩡했다. 원인은 Taichi 커널 안의 파이썬 실수 리터럴이었다. f64 값과 곱해도 리터럴은 f32로 반올림되어, `x / 6.6`이 0.1515151537(정확한 값 0.1515151515)로 계산됐다. `ti.cast(k, ti.f64)`로 감싸도 결과가 같았고 `ti.f64(k)`만 정확했다. 장부는 numpy f64로 `/ 6.6`을 하니 커널과 장부의 N/몸 비율이 1e-8만큼 어긋났다. 단계 1부터 있던 문제인데 N 흐름이 작아 기준 안에 숨어 있었다.

`run`의 화학량 계수와 `chemistry.py`의 사체 N 계산, 두 곳을 `CHEM_DTYPE(...)`로 감싸자 N 오차가 6e-16으로 내려갔다. 위 코드의 `CHEM_DTYPE(CN_RATIO)`가 그 흔적이다. 비슷한 Taichi 함정은 5절 표에 모았다.

f64로 바꾼 뒤에도 오차는 0이 아니고 시간에 따라 는다. 늘어나는 속도는 세계 상태에 따라 달랐다.

## 4. 적합도 함수 없이 선택이 일어나게 하기

점수를 매기는 함수가 없으니 선택은 "에너지가 모자라면 죽고, 충분하면 분열한다"는 것 하나로 일어나야 한다. 그러려면 능력에 비용이 붙어야 한다. 효율 유전자마다 유지비가 붙어 있어서 모든 대사를 가진 만능 세포는 쓰지도 않는 효소 값을 매 tick 낸다.

```python
o2 = ti.max(self.world.chem[O, x, y], 0.0)
e -= (self.cfg.maintenance
      + self.cfg.trait_upkeep * (eta_h + eta_m + eta_a + eta_pa + eta_po + eta_ar
                                 + eta_sf + eta_so + eta_mo + tol
                                 + self.genome[i, ETA_PRED]
                                 + self.genome[i, ADHESION])
      + self.cfg.k_brain * self.brain_cost[i]
      + self.cfg.k_tox * o2 * (1.0 - tol)) * b
```

기본 유지비 0.003에 효율 1단위당 0.004, 뇌는 가중치 절댓값 합에 비례, 산소 독성은 내성이 낮을수록 커진다. 에너지가 예비분(상한의 20%) 아래로 떨어지면 몸을 태워 호흡하는데, 수율이 높은 순서(호기 → 무산소 → 메탄 생성)로 시도한다.

분열할 때 유전자마다 가우시안 잡음을 더하고, 1% 확률로 형질 유전자 하나를 범위 안에서 균일하게 다시 뽑는다.

```python
@ti.func
def mutate(self, i: int, j: int):
    sigma = self.genome[i, MUT_RATE]
    for g in range(N_GENES):
        lo, hi = self.gene_lo[g], self.gene_hi[g]
        v = self.genome[i, g] + ti.randn() * sigma * (hi - lo)
        self.genome[j, g] = ti.min(ti.max(v, lo), hi)
    if ti.random() < self.cfg.big_mutation_p:
        n = ti.static(len(TRAIT_GENES))
        g = self.trait_idx[ti.min(ti.cast(ti.random() * n, ti.i32), n - 1)]
        self.genome[j, g] = self.gene_lo[g] + ti.random() * (self.gene_hi[g] - self.gene_lo[g])
```

돌연변이 폭(`MUT_RATE`)도 유전자라서 진화한다. 큰 변이를 형질 유전자로만 제한한 건 뇌 가중치가 들어오면서였다. 유전자가 124개로 늘자 균일 추첨이면 대사 유전자에 걸릴 확률이 약 1/7로 줄어서, 창시 세포에서 0으로 시작하는 광합성 효율 같은 유전자가 0을 벗어날 길이 좁아진다.

### 슈퍼개체와 슬롯 추첨

광합성이 번성하면 131,072 슬롯이 금방 찬다. 이때 분열을 그냥 실패시키면 슬롯을 먼저 잡은 계통이 이기는 선착순이 된다. 그래서 슬롯 하나가 같은 유전체 세포 `ncell`개를 나타내게 하고, 빈 슬롯보다 분열하려는 슬롯이 많으면 세포 수에 비례한 확률로 새 슬롯을 준다. 못 받은 슬롯은 묶음 안에서 `ncell`만 두 배가 된다.

```python
p_slot = (self.free_at_start[None] * ti.cast(self.ncell[i], ti.f64)
          / ti.max(self.div_cells[None], 1e-12))
if self.free_at_start[None] >= self.div_slots[None]:
    p_slot = 1.0  # enough free slots for every dividing slot
```

그래도 단계 3a 2차 평가에서 광합성이 번성하면 심해 열수구 군집이 사라졌다. 이 문제는 바닥 바로 위 물 칸의 세포는 수동 표류를 하지 않는 저서 부착 규칙으로 풀었고, 그 게이트(3a v2)의 20회 실행 모두에서 심해 군집이 남았다. 저서 부착은 심해 군집이 사라지는 결과를 보고 넣은 규칙이다.

## 5. GPU 커널 구성

### Taichi를 유지한 이유

NVIDIA Warp, CuPy + CUDA C도 후보였다. 단계 1이 끝날 때 CUDA, 원자 연산, 성능 중 하나라도 실패하면 Warp로 넘어가기로 정해 두었다. RTX 4050 Laptop에서 CUDA 백엔드와 f32·f64 원자 연산이 동작했고, 단일 주소 원자 연산의 직렬화는 3절의 열 부분합으로 피할 수 있어서 Taichi에 남았다. taichi 1.7.4가 Python 3.13까지만 지원해 uv로 3.12 환경을 따로 만들었다. Vulkan은 float 원자 연산 같은 확장에 기대야 해서 지원 대상에서 뺐다.

### 개체 풀과 free-list

개체 수가 변해도 메모리는 131,072 슬롯으로 고정이다. 슬롯은 이동하지 않으니 다른 슬롯을 가리킬 때 `(slot, uid)` 쌍만 들고 있으면 된다. uid는 64비트이고 재사용하지 않아서, 슬롯이 재사용됐는지는 uid만 비교하면 안다.

빈 슬롯은 원자 스택으로 관리한다. push(사망)는 `die`에서만, pop(출생)은 `reproduce`와 생물체 발생 커널에서만 한다. 한 커널 안에 push와 pop이 섞이면 스택 꼭대기를 두고 경합이 나기 때문이다. pop은 `atomic_sub`로 하고 결과가 0 이하면 `atomic_add`로 되돌린 뒤 묶음 안 분열로 처리한다. 경합 상태의 불변식(free-list 중복 없음, uid 고유, 수지)은 약 5만 마리 × 6천 tick CUDA 테스트로 확인한다.

```python
@ti.kernel
def die(self):
    """Dying bodies become detritus; slots return to the free-list (push-only kernel)."""
    for i in range(self.cap):
        if self.state[i] == DYING:
            c = self.cell(i)
            self.give(D, c.x, c.y, self.body[i])
            # ... 생략 (필드 초기화)
            self.state[i] = DEAD
            self.free[ti.atomic_add(self.top[None], 1)] = i
```

### 정렬 없이 세포 수에 비례해 뽑는 만남

포식은 칸마다 만남 후보 슬롯 하나를 뽑아 이뤄진다. 처음엔 슬롯 단위로 뽑아서 슬롯 번호에 따라 치우쳤고, 세포 수와 상관없이 슬롯마다 같은 확률로 뽑혔다. 정렬 없이 세포 수에 비례하게 뽑으려고 Efraimidis–Spirakis 가중 추출을 썼다. 키 $-\ln u / n$이 가장 작은 슬롯이 뽑히는데, 키를 양자화해 상위 비트에 넣고 슬롯 번호를 하위 비트에 붙이면 `atomic_min` 한 번으로 끝난다.

```python
u = ti.max(ti.random(ti.f64), 1e-300)
q = ti.min(-ti.log(u) / ti.cast(self.ncell[i], ti.f64) * 1e9, 1e12)
key = (ti.cast(q, ti.i64) << self.slot_bits) | ti.cast(i, ti.i64)
ti.atomic_min(self.encounter_key[c.x, c.y], key)
```

### Taichi에서 실제로 겪은 함정

| 함정 | 증상 |
|---|---|
| 커널 안에서 `cfg = self.cfg`처럼 로컬 변수로 받기 | 컴파일 오류. `ti.static(dataclass)`도 실패. 항상 `self.cfg.x`로 직접 |
| 커널 안의 `x = 0.0` | f32. f64가 필요하면 `ti.cast(0.0, CHEM_DTYPE)` |
| 테스트가 도는 중에 소스 수정 | 커널을 처음 컴파일할 때 소스를 읽어서, 중간에 바뀐 파일이 섞여 테스트 22개가 한꺼번에 실패(추정) |
| 세계마다 커널을 따로 컴파일하고 해제하지 않음 | 전체 테스트가 51% 지점에서 access violation. 테스트마다 런타임을 새로 열자 해결되고 55분 → 19분 |

## 6. 각본 없이 나온 것들

### 광합성과 대산화

창시 세포의 광합성 효율은 0이다. 단계 3a에서 처음 광합성 계통이 번성한 실행의 시간표는 이랬다.

| tick | 빛 받는 개체 | 대기 O₂ | 대기 CH₄ | 표층 R |
|---|---|---|---|---|
| 1,500 | 11 | 0 | 0.003 | 1.00 |
| 3,000 | 3,026 | 0 | 0.03 | 1.00 |
| 4,500 | 130,942 | 0.49 | 48 | 0.90 |
| 10,500 | 131,069 | 639 | 410 | 0.59 |
| 15,000 | 131,072 | 3,240 | 351 | 0.41 |
| 21,000 | 131,072 | 9,730 | 68 | 0.09 |
| 30,000 | 131,059 | 17,200 | 4.8 | 0.01 |

화학합성 → 광합성 → 사체 분해로 메탄 증가 → O₂가 환원제 R을 산화하며 소모 → R이 바닥난 뒤 O₂ 증가 → 메탄 붕괴 → 수면 온도 10.5°C에서 7.0°C로 냉각. 지구에서 일어난 순서와 같은데 일정은 하나도 넣지 않았다. 수지 오차는 전 구간 4e-13 이하였다.

다만 이 시간표는 1차 평가 수정 전 코드에서 나왔다. 빛 흡수 상한(Beer–Lambert), 성장 상한, 슈퍼개체를 넣은 뒤에는 번성이 0/41로 사라졌다. 성장 상한과 빛 공식을 각각, 또 함께 원래대로 돌려도 0/6이어서 원인에서 뺐고, 끝내 원인은 밝히지 못했다. 번성이 돌아온 건 해산 꼭대기 얕은 열수구에 붙은 매트가 빛 속에서 버티게 하는 저서 부착을 넣은 뒤였다(9/20). 매트가 광합성 계통의 발판이 된 것으로 추정한다.

이 얕은 열수구는 각본 없이 생긴 지형이 아니다. 원래 지형에서는 열수구가 모두 빛이 닿지 않는 심해에 있어 광합성이 출현할 길이 없다고 판단해, 3a 설계에서 열수구 하나를 빛이 닿는 해산 꼭대기에 두도록 지형 생성을 바꿨다. 시작 전 지형 설정이라 시작 후 개입은 아니지만, 광합성 경로를 열려고 넣은 설계 결정이다. 저서 부착은 심해 군집 소멸에 대응하려고 넣은 규칙이지만, 번성이 9/20으로 늘어난 데 영향을 준 것으로 추정한다.

### 눈덩이 지구는 처음엔 영구 상태였다

seed 7에서 광합성이 CO₂를 끌어내리고 O₂가 메탄 온실을 무너뜨리자, 수면 온도가 0°C 근처까지 내려갔다가 결빙-알베도 되먹임이 폭주해 4,000 tick 안에 바다 전체가 얼었다. 수면 온도는 이 식으로 정해진다.

$$
T_s^{\ast} = T_0 + a \ln\frac{\mathrm{CO_2}}{\mathrm{CO_2}_{\,ref}} + a_M \sqrt{\frac{\mathrm{CH_4}}{m_{ref}}} + b\,(S - 1) - c\cdot\text{결빙률},
\qquad \text{결빙률} = \mathrm{clip}\!\left(\frac{T_{\text{freeze}} - T_s}{w}, 0, 1\right)
$$

$T_0 = 15$, $a = 6$, $a_M = 4$, $b = 40$, $c = 15$, $w = 5$이고 $T_s$는 이 목표로 50 tick 시상수로 다가간다. $c/w = 3$이라 부분 결빙이 불안정하고 쌍안정이 생긴다. 히스테리시스 창은 $\ln p$ 기준 $(c - w)/a = 1.67$로, 태양 0.75에서 결빙은 pCO₂ < 0.435에서 시작하고 해빙에는 pCO₂ > 2.30이 필요하다.

결빙률이 1이면 바다-대기 기체 교환과 풍화가 모두 멈춘다. 이때 대기 CO₂를 바꿀 경로가 하나도 남지 않는다. 그래서 대기 CO₂가 4.33e4에 고정되고, 목표 온도 $15 + 6\ln 0.433 - 10 - 15 \approx -15.0$°C가 로그에 찍힌 값과 정확히 같았다. 결빙 히스테리시스 테스트는 통과하고 있었는데, 그 테스트가 외부에서 CO₂를 강제로 넣었기 때문에 실제 세계의 탈출 경로를 증명하지 못했다. 화산이 없던 코드의 뷰어를 12시간(1,632만 tick) 돌려 보니 끝까지 −15.2°C였다.

지구가 휴로니안 빙하기를 빠져나온 길은 얼음 위로 화산 CO₂가 쌓이는 것이었다. 같은 걸 넣었다. 매 tick 1% 확률로 평균 80인 지수분포 크기의 CO₂를 대기에 직접 넣고, CO₂의 5%만큼 H₂도 낸다(평균 0.8/tick으로 열수구 CO₂와 같다). 공급이 두 배가 됐으니 평형 온도가 유지되도록 풍화 계수를 1e-5에서 2e-5로 올렸고, 10만 tick 평형 온도는 6.8°C(단계 1 6.6°C)였다.

```python
if ti.random(ti.f64) < self.cfg.volcano_p:
    size = -self.cfg.volcano_mean_c * ti.log(1.0 - ti.random(ti.f64))
    h2 = self.cfg.volcano_h_frac * size
    self.world.atm[ATM_C] += size
    self.world.atm[ATM_H] += h2
    self.world.acc[SRC_C] += size
    self.world.acc[SRC_E] += 2.0 * h2
```

## 7. "나왔다"를 어떻게 판정했나

GPU 원자 연산 때문에 같은 seed라도 매번 다른 역사가 나온다. 한 번의 극적인 실행은 증거가 되지 못하니, 판정은 같은 조건 20회 실행으로 했다.

### 생존 게이트

`scripts/s4_gate.py`는 seed 1~10 × 2회를 각각 별도 프로세스로 10만 tick씩 돌리고 로그에 한 줄씩 덧붙인다. 이미 기록된 (회차, seed)는 건너뛰므로 세션이 끊겨도 이어서 돈다. 실행 하나(`survival_run.py`)는 1,000 tick마다 수지 오차, 병목 순간의 슬롯·세포 수, 빛 받는 슬롯, 생물체 통계를 모은다.

```python
while sim.tick < ticks and sim.life.count() > 0:
    sim.step(1000)
    # ... 생략 (생물체 기록)
    worst = max(worst, sim.budget_error().worst())
    alive = sim.life.state.to_numpy() == ALIVE
    pos = sim.life.pos.to_numpy()[alive].astype(int)
    photic = int((sim.world.light.to_numpy()[pos[:, 0], pos[:, 1]] > 0.01).sum())
    if first_photo is None and photic > 1000:
        first_photo = sim.tick  # first checkpoint with > 1000 cells living in light
```

존속 기준은 20회 중 16회 이상이었고 단계를 넘길 때마다 다시 쟀다. 단계 2 첫 측정만 seed 5가 2천 tick에 멸종해 9/10이었고, η 상한을 바꾼 뒤로 모든 최종 게이트가 20/20이었다. 다만 최소 슬롯은 단계마다 달랐다(단계 6에서 208, 7b에서 97, 조건 기록 게이트에서 75). 세포 수가 아닌 슬롯 수라서 7b 이후에는 병목 순간의 세포 수도 같이 기록했다(7c 최소 1,040세포).

### 사건 자동 기록과 오탐

오래 돌리면 변화가 언제 생겼는지 사람이 지켜볼 수 없어서, 2,000 tick마다 세계를 요약해 사건을 감지하고 그 순간 화면을 찍게 했다. 감지기는 한 번 켜지면 조건이 확실히 사라질 때까지 다시 켜지지 않는다.

```python
def _fire(self, key: str, cond: bool, rearm: bool) -> bool:
    """True once when cond becomes true; re-arms when `rearm` holds."""
    armed = self.armed.get(key, True)
    if armed and cond:
        self.armed[key] = False
        return True
    if not armed and rearm:
        self.armed[key] = True
    return False

# 광합성 번성: 빛 받는 슬롯 > 1,000에서 켜지고 < 100이 돼야 다시 켜진다
if self._fire("bloom", s.lit_slots > 1000, s.lit_slots < 100):
```

### 기능은 있는데 선택된 증거는 없는 주화성

7a에서 세포는 수소, 황화물, 산소, 빛을 "적응된 수준"(개체마다 기억하는 로그 평균)과 비교한 $\log(\text{지금}/\text{기억})$을 뇌 입력으로 받는다. 나빠지면 방향을 바꾸는 배선을 손으로 넣은 200개체는 정적인 수소 기울기에서 150 tick 동안 방향을 안 바꾸는 개체군보다 평균 5칸 이상 더 올라갔다. 기능은 단위 테스트로 확인된다.

문제는 진화했느냐다. 한 계통이 퍼지면 그 계통의 모든 배선이 같이 퍼지니, 먹이 감각 하나의 쏠림만 봐서는 선택인지 표류인지 모른다. 그래서 먹이와 상관없는 감각(황화물·O₂)을 대조군으로 두고 게이트 3종 × 20회의 마지막 유전체를 비교했다. 지표는 실제 뇌에 감각 −1과 +1을 넣어 "나빠질 때만 방향을 바꾸면 +1, 좋아질 때만 바꾸면 −1"이다.

| 게이트 | 먹이 감각 양수 | 먹이 감각 평균 | 대조 감각 양수 | 대조 평균 |
|---|---|---|---|---|
| 기본 | 9/20 | −0.007 | 20/40 | +0.063 |
| 뇌 비용 0 | 13/20 | +0.037 | 20/40 | +0.035 |
| 헤엄 비용 0 | 9/20 | −0.022 | 15/40 | −0.042 |

먹이 감각의 쏠림은 대조 감각과 같은 분포였다. 그 전에 기록된 "화학 감각 확산" 사건도 오탐이었다. 지금은 먹이 감각 쏠림이 대조 감각보다 0.10 이상 클 때만 사건으로 남기고, 문구도 "선택의 후보"로 적는다. 같은 이유로 3b에서도 뇌 가중치 이동은 선택의 근거에서 뺐다. 사냥 출력은 포식 효율이 없는 세포에게 비용도 이득도 없어서 조상 계통을 그대로 따르기 때문이다. 선택의 증거는 유지비가 붙은 형질(포식 효율 0에서 최대 0.93, 광합성 효율, 헤엄 속도)로만 판단했다.

## 8. 다세포 몸, 신경계, 학습

### 마디 하나가 슬롯 하나인 몸

분화 유전자와 부착 유전자가 둘 다 0.5를 넘고 세포가 16개 이상인 군체는 생물체가 된다. 마디 하나가 개체 풀의 슬롯 하나라서 몸 탄소는 그대로 `Agents.body`에 있고, 원소 장부를 고칠 필요가 없었다. 마디의 조직 비율은 몸 축 위치 $s$(머리 0, 꼬리 1)에 대한 softmax(대사 0, 근육·섬모·생식 $a + b s$)로, Hox 유전자처럼 위치에 따라 조직이 갈린다. 대사 조직 비율만큼만 먹는다.

헤엄은 저항력 이론으로 푼다. 관성을 무시하고 힘과 토크의 합이 0이 되는 몸 속도 $(V, \Omega)$를 3 × 3 선형계로 구한다. 마디마다 저항 행렬 $D = c_t\, t t^\top + c_n\, n n^\top$($c_n = 2 c_t$)이 걸린다.

### 가리비 정리에 걸린 버그

신경계(7c) 테스트로 경첩 하나만 움직이는 대조군을 만들었다. 낮은 레이놀즈 수에서 왕복 운동은 제자리여야 하는데(가리비 정리) 그렇지 않았다.

| 운동 (400 tick) | 고치기 전 | 고친 뒤 | 맞는 값 |
|---|---|---|---|
| 2마디 왕복 | 0.59칸 | 0.003 | 0 |
| 8마디 같은 위상(정상파) | 25칸, 12.7 rad 회전 | 0.001 | 0 |
| 8마디 진행파 | 21칸(옆으로) | 15.7칸(몸 축 방향으로 앞) | 앞으로 |

원인은 둘이었다. 머리 마디 방향을 좌표계에 고정해서 2마디 몸의 관절이 사실상 강체 회전이었고, 끝 모양의 속도만 쓰는 1차 적분이라 시간 대칭이 아니어서 왕복이 한쪽으로 샜다. 구슬-막대 사슬(구슬 n개 = 관절 n − 2개)로 바꾸고, 전·후 모양의 평균으로 저항을 계산하는 중점 규칙을 썼다.

```python
# midpoint rule (time-symmetric): velocities from the shape halfway through the
# tick, so a reciprocal stroke gives no net motion (scallop theorem)
rx, ry, tx, ty = self.shape(o, ph, bias, self.bend, True)
px, py, qx, qy = self.shape(o, self.phase[o], bias, self.bend_prev, False)
# ...
t = ti.math.vec2(tx[k] + qx[k], ty[k] + qy[k]).normalized()
nn = ti.math.vec2(-t.y, t.x)
D = ct * t.outer_product(t) + cn * nn.outer_product(nn)
```

이 수정 뒤에는 2마디 몸이 강체라서 근육으로 헤엄칠 수 없다(섬모만 가능, 근육 헤엄은 3마디부터). 그런데 7b 게이트에서 "2마디 몸이 118~128칸 이동"이라고 기록해 둔 게 있었다. 다시 보니 이동 거리 `travel`이 머리 위치 변화를 그대로 더해서 해류 표류(tick당 최대 0.25칸)가 섞여 있었다. 이후로는 스스로 낸 변위만 센다.

### 유전자로 키우는 신경계 회로

뉴런을 하나하나 유전자로 적으면 유전체가 끝없이 길어진다. 대신 뉴런 유형 8개마다 (개수, 마디마다 반복 여부, 시간 상수 τ, 편향, 감각 채널, 감각 이득, 운동 이득, 시냅스 밀도) 8개와 유형 간 연결 세기 8 × 8을 유전자로 두고(128개), 몸이 생기면 이 규칙으로 회로를 펼친다. 뉴런은 연속 전위 CTRNN이다.

$$
\tau \frac{dv}{dt} = -v + \sum w \tanh(v_{pre}) + \text{bias} + \text{gain} \cdot \text{sense}
$$

tick당 오일러 2번으로 적분하고 마디의 운동 뉴런 출력이 그 마디 관절을 굽힌다. 감각에는 바로 앞 관절의 굽힘(고유 감각)이 있어서, 머리 진동자 하나와 마디마다 전달 뉴런만으로도 굽힘 파동이 꼬리로 흘러간다. 근원성 리듬 0, 이 회로만으로 헤엄치는 몸을 화학합성 세포 40개에 넣고 열수구 H₂를 8배로 준 검사(검사 전용)에서는 2만 5천 tick 동안 생식 세포로 30세대가 이어졌고 스스로 헤엄친 최대 거리가 676칸이었다.

### 변화에만 반응하는 학습 조절 신호

7d에서는 유형마다 조절 뉴런 여부, 학습률, 습관화, 회복 시간을 유전자로 더해 330개가 됐다. 시냅스 변화는 3요소 규칙이다.

$$
\Delta w \leftarrow \Delta w + \eta \, m \, x_{pre} \, x_{post} - \lambda \Delta w, \qquad \lvert \Delta w \rvert \le 4, \quad \lambda = 10^{-3}
$$

1차 게이트에서 배운 변화 평균이 상한 4.0 근처(3.77, 4.0)에 붙어 있었고, 생활사 검사에서는 생물체의 97%가 "배움" 문턱을 넘었다. 조절 신호 $m$을 조절 뉴런 출력의 수준으로 둔 게 원인이었다. 조절 뉴런이 늘 켜져 있으면 같이 켜진 모든 시냅스가 평형 $\eta m x_{pre} x_{post} / \lambda \approx 10$까지 자라다 상한에서 잘린다. 연합 학습과 상관없는, 상시 활동이 만든 표류다. 도파민 뉴런이 수준이 아니라 뜻밖의 변화에 반응한다는 점을 빌려, $m$을 출력에서 최근 20 tick 평균을 뺀 변화분으로 바꿨다.

```python
m_now = msum / ti.max(mcount, 1)
m_sig = m_now - self.mod_avg[o]
self.mod_avg[o] += (m_now - self.mod_avg[o]) / MOD_TAU
self.mod[o] = m_sig
# ...
d = self.dw[g, s] + eta * m_sig * pre * post - self.cfg.learn_decay * self.dw[g, s]
self.dw[g, s] = ti.min(ti.max(d, -self.cfg.dw_max), self.cfg.dw_max)
```

연합 학습 테스트는 냄새(황화물 상승)를 배부를 때 겪은 생물체가 냄새만으로 반응 뉴런을 크게 켜는지 본다. 평가에서 대조군이 사실상 "벌"이라는 지적을 받아, 냄새와 먹이를 같은 양만큼 25 tick 떨어뜨려 겪는 진짜 비대조군을 추가했다. 짝지은 쪽은 Δ > 0.3, 비대조군은 그 10% 미만이다.

같은 평가에서 하나 더 걸렸다. 몸이 자랄 때마다 회로 전체를 다시 펼쳐서 배운 것이 지워졌다. 마디가 늘면 그 마디의 뉴런만 더하고, 몸이 끊기면 떨어진 마디의 뉴런만 반납하는 덧붙이기 발생으로 바꿨다.

## 9. 생물체는 왜 남지 못하나

기작은 다 돌아간다. 게이트에서 각본 없이 생물체가 생긴 실행은 7b 3/20, 7c 5/20(모두 신경계 보유, 최대 11마디·뉴런 178개), 7d 2/20이었고 실제로 학습한 생물체도 나왔다. 그런데 10만 tick 끝까지 살아남은 생물체는 거의 없었다. 새 기작을 더하기 전에 왜 죽는지부터 쟀다.

슬롯이 죽을 때 원인(잡아먹힘, 굶주림, 배경 사망)을 남기고, 생물체가 끝나면 머리 마디의 원인과 산 기간을 세도록 했다. 표본을 늘리려고 seed 3에서 화학합성 세포 40개에 몸 설계를 넣어 준 검사(3만 tick)에서 끝난 생물체 14마리는 전부 굶주림이었고, 32~256 tick을 살았다. 추적해 보니 머리 칸의 H₂가 약 1e-16으로 바닥났는데 한 칸 위는 0.005~0.2였다. 1~2마디 몸은 근육으로 움직일 수 없으니 바로 옆 먹이로 가지 못하고 굶는다.

| 시험 (검사 전용: seed 1~5에서 화학합성 세포 40개에 몸 설계를 넣어 줌, 3만 tick) | 끝난 생물체 | 결과 |
|---|---|---|
| 기준 (마디 0.5칸) | 67 | 모두 굶주림 |
| 마디 1칸 | 98 | 모두 굶주림. 효과 없어 되돌림 |
| 편모 유지 | 59 | 모두 굶주림. 결함 수정이라 유지 |
| 형태 형성 + 마디 0.5칸 | 61 | 모두 굶주림. 되돌림 |
| 형태 형성 + 마디 1칸 | seed 2만 약 103만 마리 | 4개 seed는 기준과 같음. seed 2는 폭발해 91%가 잡아먹힘, 산 기간 최대 1만 6천~3만 2천 tick. 되돌림 |

편모 유지는 효과와 상관없이 남겼다. 군체일 때는 세포 편모로 헤엄치다가 생물체가 되는 순간 근육과 섬모로만 움직이는 건 모형의 일관성 결함이었다. 비용이 군체 헤엄과 정확히 같도록 `k_work × drag_t = k_move`(0.01 × 1.0 = 0.01)로 맞추고 테스트로 고정했다.

평가 에이전트는 "칸 하나가 먹일 수 있는 세포 수가 전환 문턱 16보다 작다"는 구조 가설을 냈다. 생물이 없는 세계에서 한 칸에 완전 흡수원을 두고 들어오는 H₂를 재서 세포 하나의 최대 사용량 $2 \times 0.05 \times 0.93 \times 0.02 = 1.86 \times 10^{-3}$/tick으로 나눴다.

| 위치 (seed 3, 깊은 열수구 3곳) | 먹일 수 있는 세포 |
|---|---|
| 열수구 칸 | 356~392 |
| 1~3칸 위 | 170~351 |
| 8칸 위 | 55~135 |
| 바닥을 따라 1~4칸 | 156~331 |

문턱의 3~25배라 가설은 맞지 않았다. 그래서 태어날 때의 조건을 기록하는 장치를 넣고 게이트를 다시 돌렸다. 20회 중 10회에서 98마리가 생겼고 모두 121 tick 안에 굶어 죽었다. 태어난 곳의 중앙값은 바닥 바로 위, H₂ 3e-18, 같은 칸의 다른 세포 791개, 주변 8칸 292개였다. 생물체는 열수구 단세포 매트 한가운데서 태어나고, 그 칸의 먹이는 태어날 때 이미 바닥나 있다. 단세포는 분열하며 공급이 오는 길목마다 퍼지지만, 한 칸에 몰린 30세포 군체는 그 칸 몫만 받는다. 단세포 매트와 벌인 경쟁이 원인이라는 쪽을 강하게 지지하는 결과다(산 기간과 조건의 순위 상관은 $\lvert \rho \rvert \le 0.32$로 약했는데, 모두 일찍 죽어 차이가 드러날 여지가 없었다).

가끔 생물체가 폭발하는 실행도 있었다. 위 표의 seed 2는 몸 설계를 넣어 준 검사 전용 실행이다. 각본 없는 게이트에서는 7c 1회차 seed 7이 생물체 표 8,192칸을 다 채웠고, 7d 1차 게이트의 한 실행은 표 65,536칸이 1만 5천 tick 만에 찼다. 폭발한 실행에서 생물체는 수천~수만 tick을 살다가 대부분 포식자에게 먹혔다. 검사 전용 seed 2까지 세 번 모두 조건 기록 장치를 넣기 전이라, 무엇이 생물체를 살게 하는지는 아직 표본이 없다.

## 10. 한계와 다음 단계

- 육지가 없는 2D 바다 단면이고, 능력은 유전자 목록 안에서만 진화한다. 형질 목록에 없는 새 능력은 나오지 않는다.
- 사건이 지구보다 빠르다. 광합성은 2천~4천 tick, 산소 증가는 1만~3만 tick 만에 온다. 1 tick = 1,000년은 지질 사건에 맞춘 압축이고, 순서만 같다.
- 같은 역사를 다시 볼 수 없다. 난수 상태를 저장하지 않고 GPU 원자 연산이 비결정적이어서 "여기서 다시 실행"은 언제나 새 갈래다. 결정성(S1)은 CPU 단일 스레드에서만 성립한다.
- 주화성, 뉴런 수, 학습률 모두 선택된 증거가 없다. 주화성은 대조 감각과 같은 분포였고, 뉴런·학습 유전자는 비교할 생물체 계통이 오래 남지 않아 판정하지 못했다.
- 생물체는 생겼다가 굶어 사라진다. 매트를 먹는 조합(분화 + 부착 + 포식)이 진화하면 길이 열릴 수 있지만, 각본을 넣지 않는 원칙상 그 길을 직접 열어 주지는 않는다. 장기 관찰에서 폭발이 생기면 그 조건이 이제 기록된다.
- 종 거리에는 중립 유전자(색 3개, 돌연변이율)가 섞여 있어 중립 표류만으로 종이 갈라질 수 있다.
- 수지 오차가 시간에 따라 늘어나는 원인(3절 표)은 따로 잡지 않았다.

돌이켜 보면 시간이 가장 많이 든 곳은 새 기작보다 "정말 나왔는가"를 가르는 쪽이었다. 첫 대산화 시간표가 수정 뒤에 재현되지 않았고, 주화성 사건은 대조군 앞에서 사라졌고, 2마디 몸의 헤엄은 해류였다. 그래서 단계마다 20회 게이트와 대조군을 두고, 측정하지 않은 원인은 추정이라고 적었다.
